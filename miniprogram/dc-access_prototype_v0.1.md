# 数据机房外来人员准入测验微信小程序原型设计文档

## 一、项目概述

### 1.1 项目名称

**数据机房外来人员准入测验与审批系统**

暂定微信小程序名称：

> 数据机房准入测验

---

### 1.2 项目目标

本系统用于管理进入数据机房的外来人员。

外来人员到达机房后，通过扫描机房入口处的二维码进入微信小程序，完成个人信息登记和机房安全知识测验。

系统根据考试成绩自动判断是否满足准入条件：

```text
考试成绩 < 70分
        ↓
不通过
        ↓
无法发起审批
        ↓
可在规定次数内重新考试
```

```text
考试成绩 ≥ 70分
        ↓
考试通过
        ↓
后端自动创建准入审批申请
        ↓
通知机房管理员
        ↓
管理员手机审批
        ↓
批准 / 拒绝
```

如果管理员批准，则系统生成一个具有有效期的**准入二维码**，外来人员在机房入口处出示二维码，由管理员进行扫码验证。

最终形成完整的业务闭环：

```text
扫码
 ↓
信息登记
 ↓
在线考试
 ↓
后端评分
 ↓
自动创建审批
 ↓
管理员审批
 ↓
生成准入二维码
 ↓
现场扫码验证
 ↓
允许进入机房
```

# 三、前端与后端职责划分

这是本项目非常重要的设计原则。

## 3.1 微信小程序前端负责

```text
展示页面
      ↓
采集用户输入
      ↓
向后端发送请求
      ↓
接收后端返回的数据
      ↓
展示处理结果
```

具体包括：

* 扫码进入小程序
* 填写个人信息
* 展示机房安全须知
* 展示考试题目
* 收集用户选择的答案
* 提交答案
* 显示考试结果
* 显示审批状态
* 展示准入二维码
* 管理员查看审批列表
* 管理员点击批准或拒绝
* 管理员扫描准入二维码

前端**不负责**：

```text
× 正确答案判断
× 分数计算
× 判断是否及格
× 判断考试次数
× 判断是否超时
× 创建审批记录
× 修改审批状态
× 判断二维码是否有效
```

这些操作全部交给后端。

---

## 3.2 本地服务器后端负责

后端是整个系统的业务核心。

例如用户完成考试：

```text
微信小程序
    │
    │ 提交用户答案
    ▼
本地服务器
    │
    ├── 获取正确答案
    │
    ├── 计算分数
    │
    ├── 判断是否超过5分钟
    │
    ├── 判断今天是否超过3次考试
    │
    ├── 保存考试记录
    │
    └── 判断成绩
          │
          ├── <70分
          │      ↓
          │   返回未通过
          │
          └── ≥70分
                 ↓
            自动创建审批单
                 ↓
            返回待审批状态
```

因此即使有人尝试修改小程序前端代码，也不能直接伪造：

```text
考试成绩
审批通过状态
准入二维码
```

因为最终数据必须由服务器确认。

# 六、考试规则

根据目前确认的信息，考试规则如下。

| 项目         | 规则     |
| ---------- | ------ |
| 题目数量       | 10题    |
| 总分         | 100分   |
| 每题分数       | 10分    |
| 题目类型       | 单选题    |
| 是否随机抽题     | 是      |
| 考试时间       | 5分钟    |
| 每日考试次数     | 最多3次   |
| 通过分数       | 70分及以上 |
| 是否自动提交审批   | 是      |
| 是否允许主动选择提交 | 是      |

## 6.1 考试开始流程

用户点击：

```text
开始考试
```

小程序请求后端：

```text
POST /api/exam/start
```

后端执行：

```text
确认用户信息是否完整
        ↓
检查今日考试次数
        ↓
如果 < 3次
        ↓
从题库随机抽取10道题
        ↓
创建考试记录
        ↓
记录开始时间
        ↓
返回题目给小程序
```

例如：

```text
exam_id：EXAM202608200001

开始时间：
2026-08-20 14:00:00

结束时间：
2026-08-20 14:05:00
```

前端根据服务器返回的数据显示题目。

---

## 6.2 考试计时设计

虽然前端可以显示倒计时：

```text
04:59
04:58
04:57
```

但是不能只依赖前端计时。

正确设计：

```text
后端记录考试开始时间
          │
          ▼
开始时间 + 5分钟
          │
          ▼
得到考试截止时间
```

用户提交答案时：

```text
小程序
    │
    │ 提交答案
    ▼
后端
    │
    ├── 当前时间 ≤ 截止时间
    │        ↓
    │     正常判分
    │
    └── 当前时间 > 截止时间
             ↓
          考试超时
```

这样即使用户修改手机时间，也不会影响考试时间判断。

# 七、考试题目设计

假设系统题库中有100道题。

每次考试：

```text
题库
100道题
   │
   │ 后端随机抽取
   ▼
10道题
   │
   ▼
发送给小程序
```

例如：

```text
题目1
以下哪种行为禁止在机房内进行？

A. 按规定登记
B. 听从管理员安排
C. 擅自插拔设备网线
D. 在指定区域活动
```

小程序只收到：

```text
题目内容
选项
题目ID
```

例如：

```json
{
  "question_id": 15,
  "question": "以下哪种行为禁止在机房内进行？",
  "options": {
    "A": "按规定登记",
    "B": "听从管理员安排",
    "C": "擅自插拔设备网线",
    "D": "在指定区域活动"
  }
}
```

正确答案：

```text
C
```

不发送给小程序，而是保存在后端数据库。



```text

```

完整逻辑：

```text
考试提交
    │
    ▼
后端计算成绩
    │
    ├── <70
    │      ↓
    │   保存失败记录
    │
    └── ≥70
           │
           ▼
      保存通过记录
           │
           ▼

           │
           ▼

```

# 二十二、本地服务器部署结构

最终实际部署可以是：

```text
                    数据机房网络
                         │
                         ▼
                ┌────────────────┐
                │    本地服务器   │
                │                │
                │  后端 API服务  │
                │                │
                │    数据库      │
                └────────┬───────┘
                         │
                         │ HTTPS
                         │
                 ┌───────┴────────┐
                 │                │
                 ▼                ▼

```

这里需要特别注意：

> **如果微信小程序需要从外部正常访问你的本地服务器，本地服务器必须具备一个能够被微信小程序访问的合法 HTTPS 服务入口。**

因此后续实际部署时需要考虑：

```text
域名
HTTPS证书
API服务器
防火墙
网络访问控制
数据库安全
```

如果服务器只在机房内部网络中运行，而外来人员使用自己的手机扫码访问，那么还需要进一步设计：

> 外来人员的手机如何访问机房内的服务器。

这会影响最终网络架构。

# 二十三、安全设计建议

由于该系统涉及：

```text
个人信息
手机号码
公司信息
机房访问权限
准入二维码
```

建议增加以下安全机制。

---

## 23.1 不信任前端

例如前端发送：

```text
score = 100
```

后端不能相信。

正确方式：

```text
前端发送答案
        ↓
后端计算成绩
        ↓
后端返回成绩
```

---

## 23.2 考试重复提交保护

后端：

```text
exam_id
```

只能提交一次。

如果再次提交：

```text
返回：

考试已经结束
```

---

## 23.3 二维码随机Token

不要生成简单二维码：

```text
USER001
```

建议生成不可预测的随机凭证。

例如：

```text
9F7A2C81B3D4E6...
```

---

## 23.4 二维码有效状态检查

管理员扫码后，后端必须检查：

```text
二维码是否存在

是否已审批通过

是否过期

是否已经撤销

是否已经使用
```

只有全部满足：

```text
存在
+
已批准
+
未过期
+
未撤销
```

才能允许进入。

# 二十五、目前仍需要确认的关键问题

经过目前的需求确认，主体功能已经比较清晰，但还有几个会影响最终系统设计的重要问题。

## 问题 1：本地服务器的网络环境

你的本地服务器是：

### A. 可以直接连接互联网

```text
微信小程序
     ↓
互联网
     ↓
本地服务器
```

还是：

### B. 服务器只在机房内网

```text
微信
  ×
无法直接访问

机房内网
    ↓
本地服务器
```

这个问题非常关键，因为外来人员使用自己的手机访问小程序时，必须能够访问后端 API。

---

## 问题 2：二维码的有效期

管理员批准后生成的准入二维码希望：

```text
A. 一次进入后立即失效

B. 当天有效

C. 管理员设置有效时间

D. 永久有效
```

我建议：

> **C：管理员设置有效时间。**

例如：

```text
2026-08-20
08:00 - 18:00
```

超过时间自动失效。

---

## 问题 3：审批通知方式

考试通过后自动创建审批申请，那么管理员如何知道有新申请？

可以设计：

```text
A. 管理员主动打开小程序查看

B. 微信消息通知

C. 两者都有
```

建议选择：

> **C**

---

## 问题 4：同一个人员考试通过后的有效期

例如张三：

```text
今天考试80分
```

如果他明天再次进入机房，是否需要：

```text
A. 重新考试

B. 在一定时间内不用重新考试

C. 根据管理员决定
```

建议可以设置：

```text
考试通过有效期：30天
```

在30天内再次进入，只需要重新发起审批，不需要重复考试。

---

## 问题 5：管理员身份如何识别

管理员使用微信小程序审批，需要确定：

```text
A. 管理员账号密码登录

B. 绑定管理员微信身份

C. 两种结合
```

从系统安全性和使用便利性来看，我建议：

> **管理员账号 + 首次绑定微信身份。**
